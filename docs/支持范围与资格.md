# 支持范围与资格

## 1. 当前公共范围

公共 API/Worker/Web、独立参考服务、标准指标/日志/Trace 后端、当前租户权限、事件原件与附件、事务审计和 outbox、资源观察、告警工作流与中文通知构成基础范围。部分能力仍在完善中，最终支持矩阵以发行清单中的实际构建和运行证据为准。

普通遥测、轮询目录和外部告警均显示部分覆盖。平台不承诺观察到所有原生业务转换，不从当前资源状态推导原操作成功。

## 2. 资格分别记录

- 平台 F0–F3：独立公共工程的开发与限定运行资格。
- 参考 provider：仅适用于真实参考服务、其版本与环境的观察/查询能力。
- Neon provider：未接入、未启用、NOT_RUN，等待用户后续指令。
- 原业务发行门：由原系统负责人维护，不被平台部署或公共测试替代。

## 3. 当前已经验证的基线

初始独立切片已在真实 Kubernetes 和标准开源后端上运行，完成严格 TLS、匿名拒绝、角色负向、跨租户来源/原件/附件隔离、事件持久化、字节去重与冲突、原始字节摘要、实际指标/日志/Trace 结果、PostgreSQL RLS 与审计回滚检查。

这是一轮基线结果，绑定当时的镜像和配置。后续新增身份、迁移、升级或重建镜像必须补齐适用回归，不能给新制品直接继承旧摘要的 PASS。

## 4. 尚不能由上述结果推导的能力

跨节点存储 HA、任意规模性能、所有来源的可靠提交、外部消息渠道、Neon 领域接入、全部辅助技术可访问性及所有上游大版本兼容，均需要各自的真实验证。未启用的 eBPF 与持续剖析保持未验证，不显示为已提供。

测试报告应该给出源、构建、运行身份、负载、方法、结果、未覆盖项与恢复边界。HTTP 200、Pod Ready、Chart deployed 或一张截图不单独证明生产资格。
