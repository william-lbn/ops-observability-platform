# 运维与恢复

## 1. 运行档位与故障模型

首个独立验收档采用有界资源与本地持久卷，目的在于验证公共平台真实链路、权限和可恢复性。它不声明跨节点存储高可用，也不因 API 或 Collector 多副本就宣称全平台高可用。

支持范围应列出 Kubernetes、体系结构、数据库、存储类、信号后端、身份源和工具版本。生产 HA 档需要独立的数据库、对象、身份和告警故障域证据；不能沿用单机恢复的结果。

## 2. 值班检查顺序

先判断访问范围与身份能否核验，再检查平台 API、数据库、后端连接和来源新鲜度。来源失联时保留最后已知观察，并显示过期或不可读取；不要把查询失败改成空表。

| 现象 | 优先核对 | 处理边界 |
|---|---|---|
| 登录不可用 | 证书、身份来源、会话存储、主体是否停用 | 不开放匿名管理 |
| 指标/日志/Trace 查询失败 | 对应后端、查询预算、时间与来源范围 | 不扩大到任意 URL 代理 |
| 事件摄入失败 | Schema、来源权限、重复/冲突、数据库提交 | 使用同 ID 与原字节重试 |
| 证据覆盖下降 | 预期来源集合、采样、队列、观测时刻 | 不缩小分母伪造完整性 |
| 告警未送达 | 规则触发、持久通知、投影与渠道状态 | 平台失明与业务故障分别判断 |
| 资源目录过期 | Worker 身份、命名空间 RBAC、Kubernetes 读取 | 不授予全局写权限解决读取问题 |

## 3. 必须共同保护的数据

备份需要覆盖原事件字节、摘要、dedup、附件、审计、outbox、投影检查点、目录历史、告警通知、身份映射、会话与必要密钥引用。投影可重建，不代表原件与未结束责任可以提前删除。

平台 PostgreSQL 与身份数据库分别登记。Grafana 专业工具状态、Loki/Tempo 已保留遥测和 Prometheus 数据的保留/恢复承诺也应单独说明，不能由“数据库备份成功”推断所有后端均已恢复。

备份文件与原服务尽量处于不同故障域，访问和加密密钥受控。原始备份可能包含身份与安全数据，不写入公开仓库或普通聊天记录。

## 4. 恢复演练

先冻结测试目标：已 ACK 的事件、附件和审计不能丢失；同一事件重放仍被去重；冲突仍被拒绝；跨租户读取仍被拒绝；恢复时间按所选档位测量。

将备份恢复到独立数据库或隔离命名空间，核对行数、关键内容摘要、schema 版本、身份映射、dedup 与 outbox。实际读回原件和附件，不能只列出备份文件。

两个后端恢复到不同时间点时，明确标记悬空引用、未封口来源和无法判断的范围。哈希只说明内容一致性，不单独证明来源真实或整个历史完整。

## 5. 可控故障与恢复动作

故障注入只操作本平台所属进程或命名空间。可以验证 API 重启、Worker 重启、平台数据库 Pod 重建、查询后端短暂不可用与 outbox 恢复；不能为了完成公共验收重启节点、修改 CNI 或清理其他业务状态。

数据库不可写时，新的管理副作用和 ACK 失败关闭。查询后端失联时，API 返回明确错误与支持编号。规则恢复不改写原操作结果，也不消除已经记录的证据缺口。

## 6. 容量与性能

在测试前固定负载、并发、时长、样本数、资源预算、延迟阈值和统计方法。初始低资源验收可以采用固定来源、短时间窗与有限并发，但结果只适用于该规格，不对外推导大规模 SLA。

事件、普通遥测、索引、WAL、附件和备份分别估算。Collector 采用有界内存与队列，普通遥测可能丢弃；可靠事件不能在队列覆盖后仍声称完整。性能报告同时记录其他共享集群工作造成的外部变化。

## 7. 退役与数据保留

停止采集、停止通知、归档证据和删除资源是不同动作。退役应核对未结束责任、引用、保留期和备份；PVC Retain 并不代表数据已经归档，也不授权手工删除底层目录。

对暂时关闭的 provider 保留禁用和未资格状态。未来接入需要重新取得相应版本、来源与环境的资格。
