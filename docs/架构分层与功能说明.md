# 架构分层与功能说明

本文描述公共平台的工程职责与事实边界。实施状态以发行资格记录为准；设计说明不自动代表所有能力已经通过生产验收。

## 1. 产品层：用中文解释运行事实

平台的主要用户是运维值班、项目管理员和研发审计人员。共同目标是识别服务影响、查找可核实依据、理解未知范围、记录处理责任。主入口使用自有中文页面，而不是将多个开源控制台直接拼接给用户。

页面始终保留组织范围、来源、查看时间和北京时间。服务当前可读不等于原请求成功，实例数量变化不等于该请求的效果已经归因。没有采集到日志、来源不可用、没有权限和真实空结果必须分开解释。

四维状态的职责如下：

| 维度 | 含义 | 通用参考来源的处理 |
|---|---|---|
| 原请求结果 | 来源权威提交的原业务结果 | 不支持时明确“该来源未提供” |
| 资源效果 | 与原请求、对象代次和版本相匹配的效果 | 普通快照显示“待核验” |
| 服务体验 | 在特定时间和样本范围内的真实请求/探测 | 使用实际指标、请求和链路 |
| 证据覆盖 | 来源范围、采样、新鲜度、缺口和完整性 | 普通遥测与轮询只承诺部分覆盖 |

## 2. 身份与安全层：先确定谁能读取什么

每次 API、下载、导出和管理请求都执行当前授权。来源内容中的 tenant、namespace、服务标签不授予权限。平台登记表确定安全域与来源绑定，用户只能从授权来源选择受控查询。

初始身份入口支持受控个人凭据，服务端只保存其 SHA256，浏览器采用 Secure/HttpOnly/SameSite Cookie，不将令牌写入 localStorage。当前权限配置重新读取，使停用主体不能继续依赖旧页面授权。OIDC 按独立身份入口接入；必须校验 issuer、audience、签名、过期时间和登录状态，不能仅解码 JWT。

数据库运行角色必须为 NOSUPERUSER、NOBYPASSRLS。租户表使用 FORCE ROW LEVEL SECURITY，事务内通过 `set_config('app.tenant',...,true)` 设置范围；SQL 同时显式绑定 tenant。事务结束后范围不能泄漏到复用连接。迁移身份与运行身份分离。

API 服务账户不挂载 Kubernetes token。Worker 只获得本命名空间 Pod 的 get/list；不授予 Secret、写资源或 Neon 命名空间的权限。

## 3. 公共核心层：保存事实与平台自己的管理历史

`internal/store` 管理 PostgreSQL 连接、租户事务和版本化迁移。`internal/api` 组装授权、目录、查询、证据、告警和导出。`internal/worker` 负责 outbox 投影、授权资源轮询和规则状态读取。

平台自身审计有明确事务边界：业务变更、审计序号和 outbox 同一提交。事务失败时三者一起回滚。Worker 使用有界批次与 SKIP LOCKED 读取，并在同一事务写入投影和投递标记；重试不能重复生成审计事实。

这个事务只证明平台自身状态的提交。它不证明远端 Kubernetes、客户数据库或其他业务系统具有相同的原子性，也不替它们签发业务成功回执。

## 4. 证据层：原件、摘要、重复与冲突

事件按平台注册租户、来源和 eventId 去重。服务端验证公共 JSON Schema、来源绑定和允许的信号类别，保存收到的原始字节以及完整 envelope 摘要。

同一身份、相同字节的重试返回已持久保存的重复确认；同一身份而内容不同，拒绝并记录冲突。HTTP 成功只说明本次接收合同得到满足，不表示整个来源历史完整。

附件按租户和内容摘要隔离，设置大小上限，下载重新执行授权并记录审计。中文摘要是派生展示，原件下载保留原字节；不能翻译或重新序列化原件后继续沿用原摘要。

未经资格的来源不能上传 native_business_event 或 coverage_evidence。轮询、OTLP 和普通快照不自动获得可靠提交序号、封闭区间完整性或原操作归因能力。

## 5. 标准连接层：按信号管理能力和预算

| 连接器 | 上游职责 | 平台约束 |
|---|---|---|
| Prometheus | 时序指标、规则计算、标准查询 | 固定来源选择器、允许模板、时间与超时预算 |
| Loki | 日志摄入和受限查询 | 服务范围、条数上限、部分覆盖和中文错误 |
| Tempo | OTLP Trace 保存与搜索 | 服务范围、时间窗和采样未知说明 |
| OTel Collector | OTLP 接入、内存限制、批次、删除敏感属性、转发 | 固定组件清单、有界队列、明确丢弃与重试范围 |
| Kubernetes | 资源 UID 和当前状态 | 仅授权命名空间读取，不拥有控制器权力 |
| 身份源 | 登录身份与签名证明 | 当前角色映射和租户权限由平台自己执行 |

查询 URL、后端地址和凭据由受控配置决定。客户端不能传入任意 URL 或 PromQL/LogQL 片段作为代理请求。服务名按安全字符约束并转义；拒绝跟随后端重定向，避免来源查询跳转到其他网络目标。

## 6. 运行与数据层：不同数据采用不同承诺

PostgreSQL 保存平台事件、原件、附件、审计、outbox、投影、告警与目录。Prometheus、Loki、Tempo 保存普通遥测，允许有限保留和可见的退化。Harbor 负责制品分发，不保存业务证据。

参考服务是本项目独立进程，生成真实 HTTP 成功/失败、指标、中文日志和 Trace，供公共平台闭环验收。它不是 Neon 模拟成功，不提升任何 Neon 资格。

## 7. 交付层：每个资源只有一个生命周期 owner

核心 Chart 管理自研进程、平台数据库和本命名空间 RBAC。上游组件以独立 release 安装，锁定 Chart、其依赖和运行镜像。共享集群已有组件可采用 existing 模式，不能因平台连接它而获得升级或删除权。

站点 Secret、证书、registry、存储类和节点策略由仓外 overlay 提供。公开仓库保存通用模板、来源版本和验收方法；不保存真实客户信息、现场密码、内网凭据或原始运行证据。

## 8. Provider 层与未来集成

Provider 只依赖公共合同，核心不得反向导入特定产品内部包。每个 provider 独立声明来源版本、支持能力、观察结果和运行资格。

Neon provider 当前关闭。等待用户指定基线后才能进入只读接入、可靠领域证据和受控动作阶段。公共平台 F3、某个参考来源资格与 Neon 原发行门分别记录，互不替代。
