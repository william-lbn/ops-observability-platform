# 开发任务与验收

## 1. 阶段与退出口径

| 阶段 | 任务范围 | 退出证据 |
|---|---|---|
| F0 公共约束 | 001–004：范围、Core 合同、中文语义、资源归属 | 合同正反例、依赖与边界登记 |
| F1 独立工程 | 005–010：仓库、API/Worker/Web、迁移、身份、CI、镜像和 Chart | 真实构建、隔离安装、适用 E2E、实际 CI |
| F2 公共闭环 | 011–020：采集、查询、目录、审计、证据、投影、中文旅程、告警、导出与参考 provider | 真实来源与后端、权限负向、故障退化、跨信号关联 |
| F3 限定生产资格 | 021–029：供应链、性能、恢复、升级、安全、中文、支持矩阵、可选诊断与上游维护 | 同一制品、固定负载与故障模型下的可复核结果 |

Neon INT-001–008 暂停，不作为公共任务的依赖。eBPF 和持续剖析默认关闭，未启用的可选诊断不阻塞无关基础能力。

## 2. 实施责任

当前交付负责人统一维护公共合同、数据库迁移、锁文件、语言资源和发行清单。新增成员可以在明确模块内工作，不能同时各自改锁、迁移号和来源合同。原 Neon 仓库及部署统一化任务由其负责人处理。

| 模块 | 任务重点 | 必须覆盖的失败情形 |
|---|---|---|
| 身份和授权 | 当前权限、租户范围、会话、撤权 | 匿名、跨租户、过期、禁用、伪造来源、跨站请求 |
| 事件和附件 | Schema、原字节、摘要、dedup、授权下载 | 同 ID 不同内容、超限、附件越权、存储提交失败 |
| 审计和投影 | 平台事务、outbox、有界重试 | 提交前崩溃、投影失败、重复投递与恢复 |
| 查询和采集 | 真实指标/日志/Trace、取消、超时与资源预算 | 后端失联、空结果、部分结果、重定向和查询注入 |
| 目录和来源 | UID/代次、时间、范围和覆盖 | 来源重启、来源删除、过期快照和不支持能力 |
| 告警和工作流 | 症状、责任、手册、通知 | 告警风暴、低样本、通知失败与平台失明 |
| 中文页面 | 菜单、状态、错误、帮助、下载与键盘 | 无权限、无数据、数据过期、未支持和后端失败 |
| 交付和可靠性 | 源码/镜像/Chart 锁、离线、备份、升级 | 不完整闭包、镜像变化、格式变化、恢复缺口 |

## 3. 验收证据分级

开发成熟度使用 DESIGNED、IMPLEMENTED、LOCAL_VERIFIED、COMPONENT_VERIFIED、E2E_VERIFIED、RECOVERY_VERIFIED、PRODUCTION_QUALIFIED。每次晋级记录具体构建、镜像摘要、配置和检查；不能仅改一个状态字段。

来源 manifest 的 qualified.status 仍只表达该来源自身的 NOT_RUN、QUALIFIED、REJECTED 或 EXPIRED。静态合同通过、平台部署成功和当前快照不自动提升来源资格。

## 4. 当前基线

初始公共切片已经实现 API/Worker/Web、标准后端连接、当前权限、事件原件、附件、审计、outbox、目录轮询和告警读取。基础真实环境已完成部署和一轮公共 E2E；后续身份、恢复、升级、性能和浏览器资格继续按任务推进。GitHub CI 是否通过，以实际 Actions 运行记录为准。

单元测试中对缺少真实数据库而跳过的测试必须保留其跳过状态。发布门要求提供独立 PostgreSQL，不能把该项跳过后仍称数据库验收通过。真实来源和真实后端的运行用例不使用固定成功返回替代。
